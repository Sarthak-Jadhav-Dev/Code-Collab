4. Project Background / Problem Statement

Current Situation:
In the modern software development landscape, collaborative programming has become essential for team productivity and remote work. However, existing solutions either lack real-time synchronization, are too complex to set up, or require expensive subscriptions.

Limitations of Existing Systems:
• Traditional IDEs do not support real-time collaboration out of the box
• Cloud-based solutions like CodePen or Repl.it have limited features in free tiers
• Setting up collaborative environments requires significant technical expertise
• Integration of AI assistance with collaborative coding is rare
• Lack of seamless communication channels within the coding environment
• File management and project organization in collaborative settings is cumbersome
• Security and authentication in free collaborative tools is often inadequate

Why a New Software Solution is Required:
• Students and developers need an accessible, free platform for pair programming
• Real-time collaboration is essential for remote learning and distributed teams
• AI-powered code assistance can significantly improve learning outcomes
• Integrated communication reduces context switching between tools
• A comprehensive solution that combines coding, communication, and AI assistance in one platform is needed
• Open-source alternatives with modern features are limited

================================================================================

5. Vision Statement

To create an accessible, powerful, and user-friendly real-time collaborative code editor that democratizes pair programming and team-based software development. LiveCode aims to be the go-to platform for students, educators, and developers seeking seamless collaboration with integrated AI assistance, eliminating barriers to collaborative coding and fostering a culture of shared learning and innovation.

================================================================================

6. Goals

• Democratize collaborative programming by providing a free, feature-rich platform
• Enhance learning outcomes for computer science students through real-time collaboration
• Integrate cutting-edge AI technology to assist developers in coding, debugging, and learning
• Eliminate the need for complex setup and configuration in collaborative coding environments
• Foster better communication among team members with integrated chat features
• Provide a secure, scalable platform that can handle multiple concurrent users
• Create an intuitive user interface that requires minimal learning curve

7. Objectives

Performance Objectives:
• Support minimum 50 concurrent users across multiple rooms simultaneously
• Achieve real-time synchronization latency under 100ms for code changes
• Ensure 99.5% uptime for production deployment
• Provide code execution results within 3 seconds for supported languages

Feature Objectives:
• Implement real-time collaborative editing with cursor tracking for all users in a room
• Support syntax highlighting and auto-completion for at least 5 programming languages (JavaScript, Python, Java, C++, Go)
• Integrate AI assistant capable of answering coding questions with 90% relevance
• Enable secure user authentication with JWT tokens and password encryption
• Implement complete file and folder management system (CRUD operations)
• Provide group chat and AI chat with real-time message delivery
• Support code execution in the browser for at least 3 languages

Quality Objectives:
• Achieve code quality score above 85% using linting tools
• Ensure responsive design compatibility across desktop and tablet devices
• Implement comprehensive error handling with user-friendly messages
• Maintain clean, well-documented codebase with meaningful comments

8. Scope of Work

IN-SCOPE:

Authentication & User Management:
• User registration with email/password
• OTP-based email verification for signup
• Secure login with JWT token authentication
• Password recovery using OTP verification
• User session management
• Password encryption using bcrypt

Real-Time Collaboration:
• WebSocket-based real-time code synchronization using Socket.IO
• Multi-user cursor tracking and presence indicators
• Room-based collaborative sessions with unique room IDs
• User presence notifications (join/leave events)
• Synchronized file operations across all users in a room

Code Editor Features:
• Syntax highlighting for JavaScript, Python, Java, C++, and Go
• Auto-completion and intelligent code suggestions
• Multi-file editing and tab management
• Line numbering and code folding
• Search and replace functionality within files
• Code execution for JavaScript, Python, and Java

File Management System:
• Hierarchical file and folder structure
• Create, read, update, delete (CRUD) operations for files and folders
• File upload functionality for existing projects
• Automatic saving of file changes to database
• File explorer with intuitive navigation
• Rename files and folders
• Project persistence in MongoDB

Communication Features:
• Real-time group chat for team communication
• WhatsApp-style chat interface with timestamps
• Dedicated AI chat channel for code assistance
• User identification in chat messages
• Real-time message synchronization across all users
• Markdown rendering for code snippets in chat

AI Integration:
• Integration with Google Gemini AI and OpenAI
• Context-aware code assistance based on current file
• Code debugging suggestions
• Code review and optimization recommendations
• Syntax highlighting in AI responses
• Configurable AI parameters (model, temperature, max tokens)

Technical Infrastructure:
• RESTful API endpoints for file operations and authentication
• MongoDB database for user data, projects, and code storage
• Express.js backend server with CORS support
• React.js frontend with Vite build system
• Socket.IO for WebSocket communication
• Responsive UI with modern design principles

OUT-OF-SCOPE:

• Native mobile applications (iOS/Android)
• Desktop applications (Electron-based)
• Offline mode or local-first editing
• Video/audio conferencing integration
• Third-party payment gateway integration
• Marketplace for plugins or extensions
• Version control system integration (Git)
• Advanced IDE features (debugging breakpoints, profiling)
• Support for compiled languages requiring complex build systems
• Multi-language code execution beyond basic scripts
• Deployment automation and CI/CD pipelines
• Advanced project templates or boilerplates
• Collaborative whiteboard or diagramming tools
• Screen sharing functionality
• Custom theming beyond provided dark/light modes
• Export code to PDF or other document formats
• Integration with external code repositories
• Advanced admin panel for user management
• Analytics dashboard for usage statistics
• Rate limiting and API throttling for AI requests

10. Assumptions

Technical Assumptions:
• Stable internet connectivity is available for all users (minimum 2 Mbps)
• Users have modern web browsers (Chrome 90+, Firefox 88+, Edge 90+, Safari 14+)
• Users' browsers support WebSocket connections and are not blocked by firewalls
• MongoDB Atlas free tier is sufficient for development and testing
• Google Gemini API or OpenAI API access is available with sufficient quota
• Gmail SMTP is available for sending OTP emails
• Node.js version 18 or higher is installed for development

Infrastructure Assumptions:
• Free tier cloud services (Vercel, Railway, MongoDB Atlas) meet project requirements
• API rate limits for free tiers are sufficient for expected user load
• Cloud service providers maintain adequate uptime (>99%)
• Database storage remains within free tier limits during development

Collaboration Assumptions:
• Maximum 10 users per room for optimal performance
• Users collaborate within the same project scope and files
• Real-time latency under 200ms is acceptable for user experience
• File sizes remain under 5MB for optimal synchronization

Support and Feedback:
• Client/instructor provides timely feedback on deliverables within 3 business days
• Requirements are stable after initial approval of SRS document
• Weekly feedback sessions are conducted during development phase
• Issues and bugs reported are reproducible with clear steps

User Behavior Assumptions:
• Users have basic understanding of programming concepts
• Users follow best practices for password security
• Users do not intentionally attempt to break or exploit the system
• Code execution is limited to educational purposes only

11. Constraints

Time Constraints:
• Total project duration: 12-14 weeks (one semester)
• Cannot extend beyond semester end date
• Weekly milestones must be met for academic evaluation

Budget Constraints:
• Zero budget - must use only free and open-source tools
• All cloud services must remain within free tier limits
• No paid API services or subscriptions
• Cannot exceed free tier quotas for AI API calls (e.g., Gemini: 60 requests/min)

Technology Constraints:
• Must use MERN stack (MongoDB, Express, React, Node.js)
• Technology stack limited to open-source tools and libraries
• Cannot use proprietary software or paid frameworks
• Must be compatible with standard web browsers (no plugins required)
• Backend must run on Node.js version 18 or higher
• Frontend must be built with React 18+

Resource Constraints:
• Single developer/small student team with limited availability
• Development limited to after-class hours and weekends
• Limited to student knowledge and skillset
• No access to professional QA or testing teams
• Limited to personal development machines

Infrastructure Constraints:
• Hosting limited to free tier services (Vercel, Railway, Render, etc.)
• Database storage limited to MongoDB Atlas free tier (512MB)
• Cannot guarantee 100% uptime due to free tier limitations
• Bandwidth and request limits imposed by free hosting services
• Cold start delays acceptable on free tier backends

Functional Constraints:
• Code execution limited to client-safe languages (no system-level access)
• File upload size limited to 10MB per file
• Maximum 100 files per project to maintain performance
• Room capacity limited to 10 concurrent users per room
• AI responses limited by API token constraints
• Chat history limited to last 100 messages per room

Academic Constraints:
• Must meet course syllabus requirements for EDI subject
• Deliverables must align with academic evaluation criteria
• Project complexity must be appropriate for SY level
• Documentation must follow academic standards
• Source code must be original (no plagiarism)

Security Constraints:
• Cannot implement advanced enterprise-level security measures
• Limited to basic authentication (no OAuth providers)
• SSL/TLS certificates dependent on hosting provider
• No dedicated security auditing or penetration testing
• Rate limiting is basic (no advanced DDoS protection)
